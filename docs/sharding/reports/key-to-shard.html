How a key finds its shard

One function decides, and it reads only the address field of the key: shard_of_address() hashes those 32 bytes with FNV‑1a and takes the remainder modulo the shard count. Whose address it is depends on the prefix — the account's for a balance, the contract's for contract storage. Everything under one address therefore lands together, which is the whole design and also its sharpest edge.

read must match write. A lookup repeats the same routing, or it asks a shard that never held the item. There is no redirect.

shard 0 is the fallback. C keys hash wasm code rather than an address, and requests with no address at all — the db tip, view snapshots — go there.

every shard hashes only what it owns. The LtHash16 partials sum to the hash an unsharded database would produce, so the block header does not depend on the shard count.
